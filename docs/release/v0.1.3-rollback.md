# MaTE X v0.1.3 Rollback

Use when v0.1.3 artifact, release metadata, update notice, or runtime behavior is unsafe or materially incorrect.

## Stop distribution

1. Mark GitHub Release draft or remove public visibility immediately.
2. Remove affected assets from release.
3. Keep checksum and evidence copies for incident record; do not reuse them for rebuilt artifacts.
4. If tag points to wrong commit, do not move it silently. Document error, remove release, and decide whether to delete/recreate tag through explicit maintainer authorization.
5. Do not publish replacement under same artifact filename without new checksums and exact-run evidence.

## User guidance

1. State affected version, architecture, artifact names, hashes, and reason.
2. Tell users to stop launching affected build if issue is security- or data-sensitive.
3. Provide link to prior known-good release or fixed preview only after its own qualification.
4. Remind users that native updater is disabled; rollback is manual.

## Local rollback

1. Quit MaTE X.
2. Back up MaTE X user data before removal if preserving settings/evidence matters.
3. Move affected application from Applications to Trash.
4. Download prior qualified artifact from official GitHub Releases.
5. Verify its SHA-256 against that release manifest.
6. Install prior version and use Apple-provided Gatekeeper approval flow if unsigned.

Do not disable Gatekeeper or use quarantine-removal commands.

## Data and compatibility

- Do not delete `.mate-x/evidence/` unless user explicitly chooses to remove local evidence.
- Preserve repository data; MaTE X application rollback must not rewrite user repository.
- If database/schema migration is implicated, test downgrade against copied user-data directory first. Do not assume forward migration is reversible.
- If rollback cannot safely read current local state, publish blocker and recovery steps before advising downgrade.

## Replacement release

Replacement candidate must use new exact commit and rerun full contract:

```bash
bun install --frozen-lockfile
bun run check:deprecated
bun run lint
bun run typecheck
bun run test:all
bun run verify
bun run verify:release
git diff --check
```

Both native macOS architectures must regenerate artifacts, packaged E2E evidence, ASAR purity results, and SHA-256 manifests. Previous run evidence cannot qualify replacement.
